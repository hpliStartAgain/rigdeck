# 发布政策 / Release Policy

## 版本与渠道

RigDeck 使用 SemVer。公开渠道依次为 `alpha`、`beta`、`rc`、`stable`；任何渠道都必须准确描述已验证范围。

| 渠道 | 最低条件 | 不允许的表述 |
|---|---|---|
| Alpha | 核心流程可演示，已知缺失公开 | “生产就绪”“完整 GA” |
| Beta | 数据格式稳定、回滚可用、无已知 P0 | 隐瞒未支持适配器或未签名状态 |
| RC | 功能冻结、跨平台安装矩阵通过、只修发布阻塞 | 未验证更新/卸载即称 GA 候选 |
| Stable/GA | 全部发布门禁通过，工件签名与文档同步 | 任何条件豁免未书面记录 |

## GA 门禁

- 核心关键模块覆盖率 ≥ 85%，Adapter 契约/黄金夹具 100% 通过。
- P0/P1 缺陷清零；关键/高危漏洞必须修复或有维护者批准的时限例外。
- Windows/macOS 安装、升级、回滚、修复、卸载矩阵通过。
- Windows 工件完成代码签名；macOS 工件完成 Developer ID 签名与 notarization。
- 更新 manifest 签名、降级拒绝和签名失败测试通过。
- 中英文应用与文档同版本发布；Capability Matrix 带最后验证日期。
- SBOM、校验和、变更日志、已知限制和恢复说明随工件发布。

## 回滚与撤回

发现 secret 泄漏、越界写入、不可恢复的数据损坏或签名链失效时立即撤回发布。客户端不得自动降级；人工回滚仍需验证签名并保护用户 Agent 配置。

## 外部发布前人工动作

正式商标检索、域名预留、代码签名证书购买与 Apple Developer Program 开通不由构建脚本伪造。门禁未满足时只能生成未签名开发工件。
